# Retained account baseline rehearsal

The [projected preprofile metadata](../research/shared-preprofile-metadata-2026-11-04.json) was recovered from the installed contract's private baseline record without returning member rows, account/Auth fingerprints or internal IDs. It is stored migration metadata, not a backup or audit log.

The existing synthetic fixture matched its account-table shape but granted extra administrative privileges to API roles. The new disposable mode corrects only that known difference with a REVOKE of TRUNCATE, REFERENCES, TRIGGER and MAINTAIN from anon/authenticated on `public.users`. It does not invent different columns or predicates to force a pass.

`node scripts/db-runtime.mjs --preprofile-metadata-rehearsal` passed on PostgreSQL17.11: `runtime-1793811111292-411a4d0c.json`. Before applying the canonical November profile migration, it asserts equality of all captured account metadata: 19 columns, seven constraints, four indexes, four policies including permissiveness, RLS flags, 24 expanded table ACL entries and zero column ACLs. The canonical forward migration then succeeds. The canonical maintenance capture/rollback protocol restores the compared metadata and preserves synthetic user and selected Auth fingerprints, computed inside PostgreSQL without outputting values. The outer transaction rolls back and the scratch cluster is removed. Source/catalog SHA-256s and Grow commit are recorded.

Independent review identified a conditional quoting defect in embedding expected JSON inside a fixed dollar-quoted DO block. The helper now loads hex-encoded UTF-8 JSON into a temporary expected-data table outside that static block. PG17.11 evidence `runtime-1793813860581-2e9ace9b.json` verifies a harmless `$compare$` payload reaches the intended mismatch guard without syntax failure, rolls its fixture back, and then passes the actual positive forward/rollback rehearsal. Independent re-review confirmed the defect resolved and found no new scoped defect. The original catalog contained no delimiter, so its earlier evidence is not invalidated.

Separately, `--shared-profile-function-parity` passes on PG17.11: `runtime-1793810007627-7f322587.json`. All ten private profile functions and three public wrappers match the captured signatures, results, security mode, volatility, owner, ACL and full definition fingerprints. The mode asserts equality, so a mismatch fails the run. Synthetic role/timestamp helpers are excluded; their exact current definitions were recovered separately.

This is the users-table baseline and source-defined function slice. It does not establish the full 19-table application baseline, exact minor-version/collation parity, managed Auth behavior, API/Flutter compatibility or real member acceptance. A synthetic maintenance flag is not proof that production clients are offline. Production rollback would restore known weaker legacy access and requires a separately reviewed, authorized maintenance/recovery plan; this test does not authorize it.
