## Future-table default grants

The [default ACL capture](shared-default-acls-2026-11-04.json) confirms schema-scoped public table defaults for both `postgres` and `supabase_admin` grant anon/authenticated ordinary DML plus TRUNCATE, TRIGGER, REFERENCES and MAINTAIN. The installed November patch only revoked those extra privileges on 19 existing tables. It did not change defaults for future tables.

Independent review recommends a table-only, owner-specific candidate preserving DML, service_role, function/sequence defaults and private schemas. RLS does not protect TRUNCATE, but this metadata does not establish a REST exploit or a reachable SQL execution path. Reproduce PostgreSQL privilege behavior in a scratch database first; review global defaults because per-schema revokes cannot subtract global grants.

Read-only authority inspection reports `postgres` is not a superuser and is not a member of `supabase_admin`; the latter is a superuser. Do not assume the inspection role can alter the provider-owned defaults or try to elevate it. An owner-specific change must fail closed if its authority or baseline is missing. A provider-owned scope needs an authorized platform path; no partial patch is installed by this investigation.
